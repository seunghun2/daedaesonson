# 대대손손 상세페이지 가격표 세팅 가이드 (Admin/JSON)

앞으로 공원 상세페이지의 복잡한 가격표 형식을 통일하고, 프론트엔드 UI(아코디언, 탭 등)에서 고객에게 직관적으로 보이게 하기 위해 **데이터 가공 시 아래의 세팅 규칙**을 반드시 준수합니다.

## 0. 데이터 소스 우선순위 ⚠️ 최우선 규칙
* 가격 데이터의 정확도는 **출처에 따라 우선순위**가 있습니다. 상위 출처의 데이터가 있으면 하위 출처는 무시합니다.

| 우선순위 | 출처 | 설명 |
|---------|------|------|
| **1순위** | **공식 홈페이지 / 유저 제공 이미지** | 유저가 직접 홈페이지 URL이나 가격 이미지를 주면, 그것이 **가장 신뢰할 수 있는 최우선 데이터**입니다. |
| **2순위** | e하늘 장사정보 시스템 | `archive5_images/` 폴더 또는 기존 `facilities.json`의 e하늘 기반 데이터 |
| **3순위** | 기존 DB 데이터 | 이전에 세팅된 데이터 (출처 불명 시) |

* 1순위 데이터가 제공되면 기존 e하늘 데이터를 **완전히 교체**합니다.
* 공식 홈페이지 URL이 제공된 경우 `websiteUrl` 필드에도 저장하여 프론트에서 바로가기 링크를 노출합니다.

## 1. 데이터 저장 원칙 ⚠️ 최중요

### 🚫 커밋/배포 절대 금지
* **git commit, git push, 배포(deploy) 과정은 절대 하지 않습니다.**
* 로컬 어드민과 배포 어드민은 **같은 Supabase DB**를 바라보고 있으므로, 스크립트로 로컬 JSON 수정 + Supabase 동기화만 하면 로컬과 배포 서버 모두 즉시 반영됩니다.
* 별도의 커밋이나 배포 과정 없이 데이터 변경이 완료됩니다.

### 🚫 DB 대량 덮어쓰기 금지
* 과거 방식인 `DB Sync 스크립트(예: force_sync_exact.js)`를 임의로 구동하여 Supabase 전체를 덮어쓰면 안 됩니다.
* 가격 정제 스크립트는 항상 **해당 시설만** 업데이트합니다.

### 작업 프로세스
1. **원본 가격표 이미지 확인**: `archive5_images/` 폴더 내 해당 시설 이미지를 열어 실제 요금 항목, 금액 확인
2. **현재 데이터 체크**: `node scripts/check_parks_XX_YY.js` 실행하여 현재 데이터 상태 파악
3. **fix 스크립트 작성**: `scripts/fix_parks_XX_YY.js` 작성 (아래 규칙 준수)
4. **실행**: `node scripts/fix_parks_XX_YY.js` → `data/facilities.json` 로컬 수정 + Supabase 동기화
5. **검증**: check 스크립트 재실행하여 결과 확인

## 2. 요금 항목의 그룹핑 규칙
* **같은 아코디언 안에 묶기**: 항목(row)들이 프론트 화면상 하나의 아코디언 안에 들어가려면 다음 **3가지 필드 조건**이 모두 일치해야 합니다.
  1. `serviceType` (예: `BURIAL`, `BONGSAN`, `NATURAL`, `OTHER`)
  2. `subType` (예: `매장묘`, `평장묘`)
  3. `groupType` (예: `토지 분양 및 기본 매장 작업비 (필수)`)

## 3. feeType 필드의 중요성 (UI 분기 기준)
* 동일한 아코디언(같은 `subType` 및 `groupType`)이더라도 해당 요금의 **`feeType`에 따라 프론트에서는 보여지는 위치가 바뀔 수 있습니다.**
* **USAGE (기본 사용료/기본 작업비)** 
  * 토지사용료, 안장비, 굴착비, 매장작업비처럼 해당 아코디언의 메인 목록으로 노출되어야 하는 비용에는 무조건 `feeType: "USAGE"`를 설정합니다. (`INSTALLATION` 등 애매한 분류를 넣으면 '안내 및 규정'으로 빠져버릴 위험이 큽니다.)
* **MAINTENANCE (유지관리비)**
  * 관리비는 보통 `duration(N년)`, `durationType(YEAR)` 속성과 함께 입력되며, UI상 별도 안내 문구나 텍스트 블릿으로 하단에 처리될 수 있습니다.

## 4. 필수 vs 선택 옵션의 명확한 분리
* 고객이 오해하기 쉬운 부가 항목들(예: 필수 석물 비용 등)은 기존 데이터에서 `serviceType: "OTHER" (기타)`로 분류되어 있더라도, **해당 묘지를 분양받을 때 반드시 함께 구매해야 하는 속성이라면 과감히 `serviceType`을 원본 묘지 탭(예: `BURIAL`) 내부로 옮깁니다.**
* 또한, 아코디언을 나눌 때(subType 단위 혹은 groupType 기준) **괄호로 `(필수)` 또는 `(선택)`을 명확히 기재**하여 UI상에서 바로 읽히도록 합니다.
  * 예: `groupType: "석물 구매 및 조경 공사 (필수)"`

## 5. 단위 문자 필드(grade)의 활용과 절제
* `grade` 필드는 UI 화면에서 (예: • 평당) 처럼 요금 아래 작게 강조되어 보입니다.
* 불필요한 단어(`평당`, `1기당` 등)가 남용되어 복잡해지는 것을 막기 위해 가급적 `grade`는 `null` 혹은 비워두고, **단위 설명은 사용자가 읽기 쉽도록 `note(설명문)` 끝에 덧붙이는 것**을 권장합니다.
  * ❌ (기존 방식) `grade: "평당"`, `note: "기초 공사 비용입니다."`
  * ✅ (개선 방식) `grade: null`, `note: "묘역 기초 공사 비용입니다. (기준: 평당)"`

## 6. 목록의 노출 순서 (배열 Array 구조 유지)
* UI에서 노출되는 항목(row)의 순서는 `data/facilities.json` 배열에 입력된 `rows` 안의 **인덱스 순서**를 그대로 따라갑니다.
* 스크립트 가공 시 반드시 사용자가 논리적으로 읽을 수 있는 순서(예: 토지사용료 -> 매장 작업비 -> 기타 보수/축대 작업비 -> 공동 관리비 순)대로 `.splice` 연산 등을 통해 인덱스 순서를 명시적으로 정렬해 둡니다.

## 7. 원본 가격표 이미지 참고 가이드
* 파편화된 데이터를 조합하여 데이터의 정확성을 검증해야 할 때는 반드시 **원본 가격표 이미지**를 참조하여 누락 여부를 대조해야 합니다.
* 가격표 원본 이미지는 로컬 환경의 `archive5_images/` 폴더 내에 저장되어 있습니다.
  * 예: `archive5_images/26.(재)경춘공원묘원_price_info.png`
* 새로운 공원을 세팅할 때는 해당 폴더 내의 가격표 이미지를 먼저 열람하여 매장묘, 봉안당, 자연장 등 전체 카테고리 구성이 누락 없이 모두 기재되어 있는지 확인한 후 데이터 가공을 시작합니다.

## 8. 탭 분류 가이드 (serviceType 설정)
* 프론트엔드 UI의 메인 탭(예: 매장묘지, 봉안당(담), 자연장)은 `serviceType` 값에 의해 결정됩니다.
* `BURIAL` (매장묘지 탭): 매장묘, 평장묘, **야외 봉안묘/납골묘**, 야외 가족묘 등 토지를 1평이라도 차지하는 **실외형 분양 시설**은 모두 이곳에 속합니다. 이름에 "봉안"이 들어간다고 해서 `BONGSAN`으로 세팅해 불필요한 탭이 생성되지 않도록 반드시 주의해야 합니다.
* `BONGSAN` (봉안당/담 탭): 실내 봉안당이나 벽 구조의 봉안담 등 주로 **건축물 형태**의 시설에만 한정하여 사용해야 합니다.
* `NATURAL` (자연장 탭): 수목장, 잔디장, 화초장 등 토지 위에 직접 안치하는 **자연장 시설**에 사용합니다.

## 9. 설명(grade)과 추가설명(note) 필드 가이드 ⚠️ 중요
* 어드민에서 각 가격 항목별로 **2개의 텍스트 필드**를 편집할 수 있습니다.
* **⚠️ 핵심 규칙: 고객에게 보여줄 설명은 반드시 `grade` 필드에 넣어야 합니다.**
  * `grade`만 있으면 → ✅ UI에 표시됨
  * `note`만 있고 `grade` 없으면 → ❌ **UI에 표시되지 않을 수 있음** (2026-02 기준 프론트엔드 이슈)
  * 둘 다 있으면 → ✅ `grade` 먼저, `note`가 그 아래에 표시됨

### 설명 (`grade` 필드) — 🔑 UI 표시의 핵심
* **어드민 라벨**: "설명"
* **UI 위치**: 상품명과 가격 **바로 아래**에 `gray.6 / 13px` 색상으로 표시됩니다.
* **용도**: 평형, 기수, 기간, 이용자격 등 핵심 정보를 짧게 표기합니다.
  * 예: `1평당`, `2평형 (6.75㎡)`, `10년 사용`, `이용자격: 당진시민, 사용기간: 15년`
* **⚠️ 스크립트 작업 시**: 설명은 `grade`에 넣고, `note`에는 **다른 보충 설명만** 넣어야 합니다. 같은 내용을 둘 다 넣으면 **두 번 표시**됩니다!
  ```js
  // ✅ 올바른 방식 — grade에 설명, note는 비움 또는 다른 내용
  { name: '묘지 사용료', price: 592100, grade: '이용자격: 당진시민, 사용기간: 15년', note: '' }
  
  // ❌ 잘못된 방식 1 — note만 설정 (UI에 안 보임!)
  { name: '묘지 사용료', price: 592100, note: '이용자격: 당진시민, 사용기간: 15년' }
  
  // ❌ 잘못된 방식 2 — grade와 note 동일 (두 번 표시됨!)
  { name: '묘지 사용료', price: 592100, grade: '이용자격: 당진시민', note: '이용자격: 당진시민' }
  ```

### 추가설명 (`note` 필드)
* **어드민 라벨**: "추가설명"
* **UI 위치**: `grade` 아래에 `gray.6 / 12px / fw500` 스타일로 표시됩니다.
* **용도**: 해당 항목에 대한 부연 설명, 포함/불포함 내역, 주의사항 등을 기재합니다.
  * 예: `설치비, 관리비 포함`, `합장사용시 100만원 추가`, `전액 감면`, `사각묘/원형묘 약 20포 필요`
* **비워두면 표시되지 않습니다.** 필요한 항목에만 선택적으로 입력합니다.

## 10. 아코디언(subType) 말풍선 설명
* 아코디언 제목 옆에 `?` 아이콘이 표시되며, 클릭하면 해당 카테고리에 대한 고객 안내 말풍선이 나타납니다.
* 다음 키워드가 `subType` 이름에 포함되면 자동으로 말풍선이 활성화됩니다:
  * `매장묘`, `평장묘`, `봉안묘`, `봉안담`, `봉안당`, `수목장`, `잔디장`, `자연장`
  * `개장` - "기존 묘지에서 시신 또는 유골을 꺼내어 다른 곳으로 이장하거나 화장하는 작업"
  * `석물` - "묘지에 설치하는 돌로 만든 시설물 (비석, 상석, 묘테 등)"
  * `장례용품` - "매장 또는 장례에 필요한 각종 물품"
  * `매장 작업비` - "실제 매장(안장) 작업에 드는 인건비 및 장비 사용료"
  * `수리` - "기존 묘지의 석물이나 봉분을 보수하는 작업 비용"
* 새로운 말풍선 설명이 필요한 경우, `FacilityDetail.tsx`의 `getSubTypeDescription` 함수 내 `map` 객체에 키워드와 설명을 추가합니다.

## 11. feeType은 반드시 ROW 레벨에 설정 (⚠️ 중요)
* `feeType`은 `standardizedPrices` 그룹(아코디언) 레벨이 아니라, **개별 row의 속성**으로 설정해야 합니다.
* 같은 아코디언(subType) 안에서 일반 가격 항목과 관리비 항목을 함께 넣되, 관리비 행에만 `feeType: "MAINTENANCE"`를 추가합니다.
* 컴포넌트가 자동으로 `feeType: "MAINTENANCE"` 행들을 분리하여 "관리비 안내" 섹션에 표시합니다.

```json
// ✅ 올바른 구조 (row 레벨 feeType)
{
  "serviceType": "BURIAL",
  "subType": "매장묘",
  "rows": [
    { "name": "묘지사용료", "price": 1600000 },
    { "name": "연간 관리비", "price": 17000, "feeType": "MAINTENANCE" }
  ]
}

// ❌ 잘못된 구조 (group 레벨 feeType → 중복 key 에러 발생)
{ "serviceType": "BURIAL", "subType": "매장묘", "feeType": "USAGE", "rows": [...] }
{ "serviceType": "BURIAL", "subType": "매장묘", "feeType": "MAINTENANCE", "rows": [...] }
```

## 12. 관내/관외 배지 아이콘 (residency 필드)
* 공설 시설 등에서 관내/관외 가격 차이를 표시할 때는 행(row)에 `residency` 필드를 설정합니다.
* 프론트엔드에서 자동으로 색상 배지가 표시됩니다:
  * `"LOCAL"` → 🔵 파란색 "관내" 배지
  * `"NON_LOCAL"` → 🟠 주황색 "관외" 배지
  * `"VETERAN"` → 🟣 보라색 "유공자" 배지
  * `"ALL"` 또는 미설정 → 배지 없음
* 예: `{ "name": "사용료 (단장)", "price": 270000, "residency": "LOCAL" }`

## 13. [필수] 접두사로 필수 항목 구분
* 석물 등이 해당 공원에서 **의무 구매**인 경우, subType에 `[필수]` 접두사를 붙여 구분합니다.
  * 예: `"subType": "[필수]석물"` → 아코디언 제목이 "[필수]석물"로 표시
* 선택적 석물인 경우 일반 `"석물"` 또는 `"석물 (선택)"` 등으로 표기합니다.

## 13-1. feeType: STONE 사용 금지 ⚠️ 중요
* `feeType: 'STONE'`을 사용하면 **"안내 및 규정" 박스에 빠져서** 사용자에게 제대로 노출되지 않습니다.
* 석물 비용은 반드시 **별도 subType 아코디언**으로 분리하고, `feeType: 'USAGE'`를 사용합니다.
  ```json
  // ❌ 잘못된 방식 (안내 및 규정 박스에 빠짐)
  { "name": "단장 석물비", "price": 305000, "feeType": "STONE", "groupType": "부가옵션" }

  // ✅ 올바른 방식 (별도 아코디언으로 분리)
  {
    "serviceType": "BURIAL", "subType": "석물", "unit": "원",
    "rows": [
      { "name": "단장 석물비", "price": 305000, "feeType": "USAGE" }
    ]
  }
  ```

## 13-2. 개인/부부 중복단 처리 (봉안당 시설)
* 봉안당 시설에서 같은 그룹(예: A관) 안에 **같은 단이 2번** 나타나는 경우, 개인/부부 가격이 구분 없이 섞여있는 것입니다.
* 이 경우 **subType을 `봉안당(개인)` / `봉안당(부부)`로 분리**하여 별도 아코디언으로 만듭니다.
  ```json
  // ❌ 잘못된 방식 (같은 그룹에 같은 단이 2번)
  { "subType": "봉안당", "rows": [
    { "name": "10단", "price": 1200000, "groupType": "A관" },
    { "name": "10단", "price": 2900000, "groupType": "A관" }  // 어떤 게 개인? 부부?
  ]}

  // ✅ 올바른 방식 (개인/부부 아코디언 분리)
  { "subType": "봉안당(개인)", "rows": [
    { "name": "10단", "price": 1200000, "groupType": "A관" }
  ]}
  { "subType": "봉안당(부부)", "rows": [
    { "name": "10단", "price": 2900000, "groupType": "A관" }
  ]}
  ```
* 일반적으로 원본 데이터에서 **전반부(낮은 가격)가 개인, 후반부(높은 가격)가 부부**입니다.

## 13-3. 복합단 표기 쪼개기
* `1,7단`, `4,5단` 처럼 **쉼표로 묶인 복합 단 표기**는 개별 단으로 분리합니다.
* 가격은 동일하게 복사합니다.
  ```
  // ❌ 복합 표기
  { "name": "1,7단", "price": 2500000 }

  // ✅ 개별 분리
  { "name": "1단", "price": 2500000 }
  { "name": "7단", "price": 2500000 }
  ```

## 13-4. 범위단 표기 개별 분리
* `1단~3단`, `8단~11단` 처럼 **범위(~)로 묶인 단 표기**는 개별 단으로 분리합니다.
* 가격은 동일하게 복사합니다.
  ```
  // ❌ 범위 묶음 표기
  { "name": "1단~2단", "price": 4500000 }
  { "name": "3단~7단", "price": 5500000 }

  // ✅ 개별 분리
  { "name": "1단", "price": 4500000 }
  { "name": "2단", "price": 4500000 }
  { "name": "3단", "price": 5500000 }
  { "name": "4단", "price": 5500000 }
  ...
  ```
* §13-3의 쉼표(,) 분리와 동일한 원칙입니다.

## 13-5. 부대용품(유골함 등)은 기타(OTHER) 탭 사용 금지 ⚠️ 중요
* 유골함, 수의 등 부대용품은 **별도 serviceType: OTHER 탭으로 만들지 않습니다.**
* 해당 시설의 **메인 serviceType 아코디언(봉안당, 매장묘 등) 안에 행(row)으로 추가**합니다.
* 기타(OTHER) 탭이 생기면 UI에서 불필요한 탭이 추가되어 사용자 경험이 나빠집니다.
  ```json
  // ❌ 잘못된 방식 (기타 탭 생성)
  { "serviceType": "OTHER", "subType": "장례용품", "rows": [
    { "name": "유골함", "price": 650000 }
  ]}

  // ✅ 올바른 방식 (봉안당 아코디언 안에 행으로 추가)
  { "serviceType": "BONGSAN", "subType": "봉안당", "rows": [
    { "name": "1단", "price": 4500000, "feeType": "USAGE" },
    ...
    { "name": "유골함", "price": 650000, "feeType": "USAGE", "grade": "별도 구매" }
  ]}
  ```

## 14. CHARNEL serviceType 주의사항
* `CHARNEL` serviceType은 프론트엔드에서 한글 탭명 매핑이 되어있지 않아 **영어 그대로 "CHARNEL"로 표시**될 수 있습니다.
* 봉안당/봉안담 관련 시설은 반드시 `BONGSAN`을 사용해야 합니다.
* 단, 납골당 등 특수한 경우에는 `CHARNEL`을 매장묘지 탭 내의 행으로 처리하거나, 별도 탭 매핑을 추가해야 합니다.

## 15. 대표 가격 ★ 표시 (isRepresentative) ⚠️ 중요
* 상세 페이지의 서비스 타입별 대표 가격(★ 별 마크)은 **`isRepresentative: true`** 로 지정합니다.
* 최저가 자동 계산이 아니라, **명시적으로 지정한 행의 가격**이 대표가로 노출됩니다.
* 반드시 **사용료(묘지대, 봉안료 등 본질적인 분양/이용 비용)** 행에만 설정해야 합니다.
* 석물비, 작업비, 관리비 등 부대비용에는 설정하지 않습니다.
* 어드민 페이지에서는 ★ 버튼으로 토글 가능합니다.

```json
// ✅ 올바른 사용
{ "name": "묘지 사용료", "price": 1000000, "isRepresentative": true }

// ❌ 잘못된 사용 (석물에 별 마크)
{ "name": "상석", "price": 715000, "isRepresentative": true }
```

* **우선순위**: `isRepresentative` 행이 있으면 그 중 최저가 → 없으면 USAGE 행 중 10만원 이상 최저가
* 각 serviceType(BURIAL, BONGSAN 등)별로 독립적으로 계산됩니다.

## 16. 아코디언 말풍선(?) 설명 (getSubTypeDescription)
* 아코디언 제목 옆 `?` 아이콘을 누르면 설명 팝업이 표시됩니다.
* `FacilityDetail.tsx`의 `getSubTypeDescription` 함수에 등록된 키워드만 표시됩니다.
* 현재 등록된 키워드 목록:
  * `매장묘` - 시신을 땅에 묻는 전통 장법
  * `복합묘` - 매장묘+봉안묘 결합
  * `평장묘` - 봉분 없이 평평하게 조성
  * `단장형` - 1인용 묘지
  * `합장형` - 2인용 묘지 (부부 등)
  * `봉안묘` - 화장 후 묘지 형태 안치
  * `봉안분묘` - 봉안묘와 같은 개념
  * `봉안담` - 담 형태 안치
  * `봉안당` - 납골당 안치
  * `납골` - 납골당(봉안당) 안치
  * `수목장` / `잔디장` / `자연장` - 친환경 장법
  * `개장` - 이장/화장 작업
  * `석물` - 비석, 상석, 묘테 등
  * `장례용품` - 유골함, 석관 등
  * `매장 작업비` - 안장 작업 인건비
  * `수리` - 석물/봉분 보수
* 매칭 방식: `subType.includes(key) || key.includes(subType)` 이므로 부분일치 가능
* 새 키워드 추가 시 `getSubTypeDescription` 함수의 `map` 객체에 추가합니다.

## 17. 배치 가격 정제 워크플로우 (10개 단위)

공설묘지/공원묘원의 가격 데이터를 10개 단위로 검수·정제하는 표준 프로세스입니다.

### 작업 순서

#### Step 1: 현재 데이터 확인 스크립트
```bash
# scripts/check_parks_XXX_YYY.js 작성 후 실행
node scripts/check_parks_181_190.js
```
출력 형식: `[serviceType] subType → name = price | grade | fee | res | ★`

#### Step 2: 원본 이미지 대조
```
archive5_images/181.장수동공설묘지(매장불가)_price_info.png
archive5_images/182.황산병온공설묘지_price_info.png
...
```
이미지를 열어 현재 데이터와 비교하여 다음 항목을 체크:

| 체크 항목 | 예시 |
|---------|-----|
| **feeType 오분류** | `EXTENSION` → `USAGE` (사용료인데 연장료로 잘못 분류) |
| **residency 오분류** | `RESIDENT` → `LOCAL` (관내 배지 표시용) |
| **serviceType 오분류** | `BONGSAN` → 야외 봉안묘는 `BURIAL` 안에 포함 |
| **관리비 누락** | 이미지에 관리비 있는데 데이터에 없는 경우 |
| **grade 정리** | 괄호 안 닫힘, 불필요 정보, 사용기간 누락 등 |
| **isRepresentative 확인** | 사용료에만 ★, 관리비·석물에는 제거 |
| **단장형/합장형 분리** | 불필요한 subType 분리 → 매장묘로 통합 |
| **미분류 groupType** | `groupType: '미분류'` → 삭제 |

#### Step 3: 수정 스크립트 작성 및 실행
```js
// scripts/fix_parks_XXX_YYY.js
const { createClient } = require('@supabase/supabase-js');
const fs = require('fs');
const path = require('path');

async function fix() {
    const fp = path.join(__dirname, '../data/facilities.json');
    const data = JSON.parse(fs.readFileSync(fp, 'utf8'));
    const supabase = createClient(SUPABASE_URL, SUPABASE_KEY);

    function update(id, fn) {
        const p = data.find(x => x.id === id);
        if (!p) { console.log('NOT FOUND:', id); return; }
        if (!p.priceInfo) p.priceInfo = {};
        fn(p);
        console.log('✅', id, p.name);
    }

    // 각 시설별 수정
    update('park-XXXX', p => {
        p.priceInfo.standardizedPrices = [
            {
                serviceType: 'BURIAL', subType: '매장묘', unit: '원',
                rows: [
                    { name: '묘지 사용료', price: 90000, feeType: 'USAGE', grade: '15년 사용', isRepresentative: true },
                    { name: '묘지 관리비', price: 100000, feeType: 'MAINTENANCE', grade: '15년 사용' },
                ]
            }
        ];
    });

    // 저장
    fs.writeFileSync(fp, JSON.stringify(data, null, 2), 'utf8');

    // Supabase 동기화 (pricing + representativePrice 함께 업데이트!)
    const ids = ['park-XXXX', ...];
    for (const id of ids) {
        const f = data.find(d => d.id === id);
        // ⚠️ representativePrice 자동 계산 (isRepresentative 행 중 최저가)
        let repPrice = 0;
        for (const g of (f.priceInfo?.standardizedPrices || [])) {
            for (const r of (g.rows || [])) {
                if (r.isRepresentative && r.price > 0 && (repPrice === 0 || r.price < repPrice)) {
                    repPrice = r.price;
                }
            }
        }
        const { error } = await supabase
            .from('Facility')
            .update({ 
                pricing: JSON.stringify(f.priceInfo),
                representativePrice: repPrice || undefined,
            })
            .eq('id', id);
        if (error) console.log('❌', id, error.message);
    }
}
fix();
```

### 자주 발생하는 수정 패턴

| 패턴 | Before | After |
|-----|--------|-------|
| **EXTENSION→USAGE** | `feeType: 'EXTENSION'` | `feeType: 'USAGE'` (사용료는 USAGE) |
| **RESIDENT→LOCAL** | `residency: 'RESIDENT'` | `residency: 'LOCAL'` (관내 배지 표시) |
| **BONGSAN→BURIAL 내 포함** | 별도 `serviceType: 'BONGSAN'` | `BURIAL` rows 안에 봉안묘 행 추가 |
| **단장형/합장형 통합** | 별도 subType으로 분리 | `매장묘` 안에 `(단장)`, `(합장)` row로 통합 |
| **관리비 누락 추가** | 사용료만 있음 | `feeType: 'MAINTENANCE'` 행 추가 |
| **grade에 사용기간 추가** | grade 비어있음 | `'이용자격: OO군민, 사용기간: 15년'` |
| **미분류 groupType 삭제** | `groupType: '미분류'` | groupType 필드 제거 또는 올바른 이름 부여 |
| **연장료→관리비 안내** | `feeType: 'EXTENSION'` (안내 및 규정에 표시됨) | `feeType: 'MAINTENANCE'` (관리비 안내에 표시됨) |
| **STONE→별도 아코디언** | `feeType: 'STONE'` (안내 및 규정에 빠짐) | 별도 `subType: '석물'` 아코디언 + `feeType: 'USAGE'` |
| **OTHER→BONGSAN** | 봉안당/봉안담이 `serviceType: 'OTHER'` | `serviceType: 'BONGSAN'`으로 변경 |
| **개인/부부 중복단 분리** | 같은 그룹에 같은 단이 2번 | `subType: '봉안당(개인)'` / `'봉안당(부부)'`로 분리 |
| **복합단 쪼개기** | `name: '1,7단'` | `'1단'` + `'7단'` 개별 행으로 분리 |
| **정면/측면 그룹 분리** | grade에 '정면' 표기 | `groupType: 'B관(정면)'` 별도 탭으로 분리 |

## 18. 공식 홈페이지 바로가기 링크 (websiteUrl)
* 시설의 공식 홈페이지 URL이 있는 경우, **어드민에서 `websiteUrl` 필드에 입력**하면 가격 섹션 하단에 자동으로 "공식 홈페이지 바로가기" 링크가 노출됩니다.
* `websiteUrl`이 없는 시설에는 링크가 표시되지 않습니다.

### UI 표시 위치
```
가격 탭/테이블
  ↓
면책 안내 텍스트 (배경 없음)
  ↓
─────────────────────────── (구분선)
○○○ 공식 홈페이지  바로가기 ↗
```

### 스타일
* 시설명 + "공식 홈페이지" → 검은색 (`dark.7`)
* "바로가기" + ExternalLink SVG 아이콘 → 본컬러 (`brand.6`)
* 상단 구분선 (`1px solid #e9ecef`)
* 새 탭에서 열림 (`target="_blank"`)

### 세팅 방법
1. **어드민**: 시설 편집 → `websiteUrl` 필드에 URL 입력 (예: `https://seohopark.kr`)
2. **스크립트**: `p.websiteUrl = 'https://example.com';` + Supabase update에 `websiteUrl` 포함
3. **주의**: 위치 섹션의 별도 홈페이지 버튼은 제거됨 → `websiteUrl`은 가격 섹션에서만 노출
