## 3. 카카오 로그인 세션 유지 문제 해결

### 문제 분석 (Sequential Thinking MCP 활용)
- **증상**: 로컬에서는 정상, 배포 환경(daedaesonson.com)에서 로그인 직후 세션 풀림
- **원인 1**: `signInWithPassword` 중복 호출
  - 서버(callback)에서 1번, 클라이언트(AuthProvider)에서 1번 → 총 2번
  - 두 번째 호출이 첫 번째 세션을 무효화
- **원인 2**: Vercel 환경변수 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 누락
  - `NEXT_PUBLIC_` 접두사 변수는 빌드 타임에 주입되므로, Vercel에 없으면 서버/클라이언트 모두 `undefined`
- **진단 방법**: 임시 `/api/debug/env-check` 엔드포인트 생성 → curl로 각 변수 존재 여부 확인

### 카카오 콜백 수정
- **수정 파일**: `app/auth/callback/route.ts` (전면 재작성)
- **변경 전**: 서버에서 `signInWithPassword` → `email:password`를 base64로 쿼리 전달 → 클라이언트에서 다시 `signInWithPassword`
- **변경 후**: 서버에서 `signInWithPassword` → `access_token`/`refresh_token`을 base64로 전달 → 클라이언트에서 `setSession()` 직접 호출
- Raw fetch 대신 **Supabase JS admin client** 사용:
  ```ts
  const supabaseAdmin = createClient(supabaseUrl, serviceKey, {
      auth: { autoRefreshToken: false, persistSession: false }
  });
  // admin.listUsers(), admin.createUser(), admin.updateUserById() 사용
  ```
- 환경변수 사전 검증 추가: 누락 시 `/?login_error=env`로 리다이렉트

### AuthProvider 수정
- **수정 파일**: `components/auth/AuthProvider.tsx`
- `kakao_auth` 파라미터 → `kakao_session` 파라미터로 변경
- `signInWithPassword` 호출 → `setSession({ access_token, refresh_token })` 호출로 변경
- 중복 세션 생성 문제 완전 제거

## 4. OTP 휴대전화 로그인 수정

### 문제
- 배포 환경에서 OTP 인증 시 "서버 오류가 발생했습니다" 또는 "서버 설정 오류입니다"

### 수정
- **수정 파일**: `app/api/auth/verify-otp/route.ts` (전면 재작성)
- Raw fetch → **Supabase JS admin client** 사용
- `per_page=50` → `perPage: 1000`으로 확대 (유저 검색 누락 방지)
- 모든 단계에 상세 에러 로깅 추가:
  ```
  [verify-otp] OTP lookup error: ...
  [verify-otp] listUsers error: ...
  [verify-otp] createUser error: ...
  [verify-otp] signIn error: ...
  ```
- 환경변수 사전 검증: `serviceKey`, `supabaseUrl`, `anonKey` 중 하나라도 없으면 명확한 에러 반환
